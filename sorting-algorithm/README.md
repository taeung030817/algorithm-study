#2. Sorting Algorithms (정렬 알고리즘)

## 왜 배우는가

정렬 알고리즘은 실무에서 직접 손으로 구현할 일이 거의 없다. 대부분 언어나 라이브러리가 이미 최적화된 정렬 함수를 제공하기 때문이다. 그럼에도 배우는 이유는, 정렬 알고리즘들이 "같은 문제를 어떤 관점으로 보느냐"에 따라 접근 방식이 완전히 달라질 수 있다는 걸 가장 명확하게 보여주기 때문이다.

## Bubble Sort

인접한 두 값을 비교해서 순서가 잘못됐으면 서로 교체한다. 이 과정을 반복하면 가장 큰 값이 한 번씩 뒤로 밀려나면서 끝자리로 이동한다.

- 방식은 직관적이지만, 이미 정렬된 값끼리도 계속 비교하게 되어 낭비가 많다.

## Selection Sort

Bubble sort처럼 잘못된 쌍을 찾을 때마다 바로 바로 교체하는 대신, 남은 구간에서 가장 작은 값을 찾아 그 자리로 딱 한 번만 옮긴다. 그다음으로 작은 값도 같은 방식으로 찾아 옮긴다.

예: 숫자가 6개면 맨 앞자리부터 남은 값들과 비교해서 가장 작은 값을 앞으로 보내고, 그다음 자리도 같은 방식 반복 → 비교 횟수는 5+4+3+2+1 = 15번.

- 교체(swap) 횟수는 bubble sort보다 훨씬 적지만, 매번 남은 구간 전체를 뒤져서 최솟값을 찾아야 한다는 점은 그대로 남는다.

## Insertion Sort

리스트를 "이미 정렬된 구간"과 "아직 정렬 안 된 구간"으로 나눈다고 생각한다. 정렬 안 된 값을 하나씩 꺼내서, 정렬된 구간 안에서 자기 자리를 찾을 때까지 왼쪽으로 밀어 넣는다.

## 위 세 알고리즘의 공통된 약점

Bubble, Selection, Insertion sort 모두 거의 모든 항목끼리 서로 비교한다는 공통점이 있다. 그래서 데이터 양이 2배로 늘면 작업량은 4배로 늘어난다.

시간복잡도: **O(n²)**

이 문제를 피하려면 리스트 전체를 하나의 거대한 문제로 다루지 않는 접근이 필요하다.

## Merge Sort

전체 데이터를 절반으로 나누고, 그 절반을 또 절반으로 나누는 걸 각 조각에 항목이 하나만 남을 때까지 반복한다 (분할, divide). 그다음 다시 위로 올라오면서 조각들을 순서대로 합친다 (병합, merge).

- 데이터가 백만 개여도 약 20단계 정도면 끝난다. 데이터가 늘어나도 작업량은 완만하게 증가한다 (**O(n log n)**).
- 다만 조각들을 다시 합칠 때 임시로 사용할 두 번째 리스트(보조 공간)가 필요하다.

여기서 자연스러운 질문: 보조 리스트 없이 비슷한 속도를 낼 수는 없을까?

## Quick Sort

피벗(기준값)을 하나 정해서, 피벗보다 작은 값은 왼쪽으로, 큰 값은 오른쪽으로 보낸다. 이 과정을 각 구간에서 반복한다.

- 별도의 보조 리스트 없이 제자리(in-place)에서 정렬이 가능하다.
- 피벗을 잘 선택하면 속도와 균형을 동시에 잡을 수 있지만, 계속 안 좋은 피벗이 선택되면 성능이 크게 떨어질 수 있다 (최악의 경우 O(n²)).

## 실제로는 여러 알고리즘을 결합해서 쓴다

예를 들어 파이썬의 기본 정렬(Timsort)은 다음과 같이 동작한다:

1. 데이터 안에서 이미 정렬된 구간을 먼저 찾는다
2. 작고 지저분한 구간은 insertion sort로 정리한다
3. 정리된 구간들을 merge sort 방식으로 효율적으로 합친다

## 정렬의 또 다른 가치

정렬은 단순히 데이터를 순서대로 나열하는 것 이상의 의미가 있다. 값들이 순서대로 정렬되어 있으면, 그 순서 자체가 유용한 정보가 된다.

값이 너무 크거나 너무 작다는 걸 한 번만 비교해도 알 수 있기 때문에, 가능성 없는 쌍을 한꺼번에 제거할 수 있다. 이 아이디어가 다음에 배울 **Two Pointers** 기법으로 이어진다.
