# 3. Two Pointers (투 포인터)

## 개념

두 개의 포인터를 이용해서 탐색 범위와 위치를 효율적으로 관리하는 기법이다.

## 문제: 두 수의 합

목표: 정렬된 리스트에서, 합이 target이 되는 두 값의 쌍을 찾는다.

### Brute force

가장 확실한 방법은 모든 쌍을 다 시도해보는 것이다. 하지만 이러면 확인해야 할 조합 수가 너무 많아져서 **O(n²)**에 갇힌다.

### Two Pointers 방식

모든 쌍을 비교하는 대신, 가장 멀리 떨어진 쌍(맨 앞 값 + 맨 뒤 값)부터 비교한다.

- 합이 target보다 **작으면** → 왼쪽 포인터를 오른쪽으로 이동
- 합이 target보다 **크면** → 오른쪽 포인터를 왼쪽으로 이동

이렇게 하면 성립할 수 없는 조합을 통째로 제거할 수 있다. 각 포인터가 리스트를 한 번씩만 통과하기 때문에 **O(n)**만에 끝난다.

**예시**: `[1, 2, 4, 6, 8, 9, 14, 15]`, target = 13

```
left=1, right=15 → 합 16 (> 13) → right 이동
left=1, right=14 → 합 15 (> 13) → right 이동
left=1, right=9  → 합 10 (< 13) → left 이동
left=2, right=9  → 합 11 (< 13) → left 이동
left=4, right=9  → 합 13 (= 13) → 정답: (4, 9)
```

## 같은 아이디어의 다른 응용: Palindrome / Reverse

포인터를 양 끝에서 시작해 서로를 향해 좁혀오는 같은 방식으로, 문자열이 회문(palindrome)인지 판별하거나 리스트를 제자리에서 뒤집을 수도 있다.

## 포인터가 항상 서로를 향할 필요는 없다

Two pointers가 꼭 서로 마주 보며 좁혀드는 형태일 필요는 없다.

예를 들어 한 포인터는 리스트의 모든 값을 순서대로 읽어나가고(reader), 다른 포인터는 다음에 올 고유값이 위치해야 할 자리를 표시(writer)하는 방식도 있다 — "한 포인터는 조사하고, 한 포인터는 결과를 만드는" 구조다. 중복 제거 같은 문제에 쓰인다.

## 속도가 다른 두 포인터 (Fast & Slow)

두 포인터의 이동 속도를 다르게 줄 수도 있다. 한 포인터는 한 번에 1칸, 다른 포인터는 한 번에 2칸씩 이동하는 식이다.

- 구조에 루프(cycle)가 **없다면**: 빠른 포인터가 끝에 도달했을 때 종료
- 구조에 루프가 **있다면**: 두 포인터가 서로 만나는 순간 종료 → 연결 리스트의 사이클 존재 여부를 판별할 때 쓰인다

## 공통 원리

방식은 다르게 보여도 원리는 항상 같다: 두 포인터가 항상 "유용한 관계"를 유지하도록 이동시킨다.

이 과정에서 건너뛰는(skip) 구간이 반드시 생기는데, "그 구간에는 정답이 없다"는 논리적 근거가 확실할 때만 two pointers 기법이 성립한다.

## 다음 주제

여기까지는 개별적인 값들의 관계만 추적했다. 하지만 정답이 하나의 연속된 구간(boundary) 자체여야 한다면 어떻게 할까? → 이 질문이 **Sliding Window**로 이어진다.
