#3. Sliding Window (슬라이딩 윈도우)

## 개념

두 포인터로 단일 위치가 아니라 연속된 구간(윈도우)의 양쪽 경계를 추적하는 기법이다. 두 포인터가 하나의 연속된 구간의 경계를 이룰 때 sliding window가 된다.

여기서 "연속된(contiguous)"이란 배열이나 문자열에서 끊기지 않고 이어지는 구간을 말한다.

## 고정 크기 윈도우: 서버 트래픽 예시

서버가 있고, 어떤 60초 구간의 트래픽이 가장 많았는지 모니터링해야 한다고 하자.

**나쁜 방법 (매번 다시 계산)**: 0~60초 구간 합을 구하고, 다음엔 1~61초 구간 합을 처음부터 다시 60개 다 더한다면 낭비가 크다.

**Sliding Window (업데이트만)**: 윈도우를 한 칸 옮길 때, 60개 값 중 59개는 그대로 유지된다. 딱 하나의 값만 빠져나가고 하나의 값만 새로 들어온다. 그러므로 처음 한 번만 전체를 계산하고, 그다음부터는 **나가는 값을 빼고 들어오는 값을 더하기만** 하면 된다. 윈도우가 아무리 넓어도 매 이동마다 딱 두 번의 연산이면 충분하다.

**예시** (윈도우 크기 3): `[4, 2, 7, 1, 5, 3]`

```
[4,2,7]      합 = 13
4를 빼고 1을 더함 → 13-4+1 = 10   → [2,7,1]
2를 빼고 5를 더함 → 10-2+5 = 13   → [7,1,5]
7을 빼고 3을 더함 → 13-7+3 = 9    → [1,5,3]
최댓값: 13
```

## 윈도우 크기가 정해지지 않았다면: 가변 윈도우

문제에서 윈도우 크기를 미리 정해주지 않으면, 윈도우가 스스로 늘어나고 줄어들어야 한다.

### 예시: 중복 없는 가장 긴 부분 문자열

문자열에서, 중복되는 문자가 없는 가장 긴 연속 부분 문자열을 찾는 문제.

- 오른쪽 경계를 확장하면서 새 문자를 탐색한다.
- 확장하다가 창 안에 이미 있는 문자와 중복되면, 그 순간 창이 무효화된다.
- 왼쪽 경계를 오른쪽으로 옮겨서 중복이 사라질 때까지 좁힌다 (이동하는 동안 오른쪽 경계는 고정).
- 중복이 사라지면 다시 오른쪽 경계를 확장한다.

**예시**: `"abcabcbb"`

```
r=0 'a' → 창 {a}         길이 1
r=1 'b' → 창 {a,b}       길이 2
r=2 'c' → 창 {a,b,c}     길이 3  ← 최댓값
r=3 'a' → 중복! l 이동   → 창 {b,c,a}
r=4 'b' → 중복! l 이동   → 창 {c,a,b}
r=5 'c' → 중복! l 이동   → 창 {a,b,c}
r=6 'b' → 중복! l 이동   → 창 {c,b}
r=7 'b' → 중복! l 이동   → 창 {b}
최종 답: 3 ("abc")
```

## 왜 이게 O(n²)이 아니라 O(n)일까

오른쪽 포인터를 늘리는 루프 안에 왼쪽 포인터를 옮기는 루프가 또 있어서 언뜻 O(n²)처럼 보인다.

하지만 두 포인터 모두 **뒤로 움직이지 않는다.** 즉 각 문자는 창에 딱 한 번 들어오고 딱 한 번 나간다. 그래서 전체 작업량은 여전히 **O(n)**이다.

핵심은 창(window)에 적용할 규칙을 단순하게 정하는 것이다.

## 핵심 아이디어

Sliding window는 단순히 경계를 옮기는 기법이 아니다. **현재 창에서 얻은 유용한 정보를 다음 창으로 그대로 이어받아 재사용하는 기법**이다.

## 한계

Sliding window는 배열이나 문자열처럼 데이터가 일직선(flat)으로 나열돼 있을 때 효과적이다.

하지만 모든 데이터가 이렇게 평평하지는 않다. 메뉴 안에 메뉴가 있거나, 폴더 안에 폴더가 있거나, 트리 구조의 노드처럼 가지(branch)를 치는 구조도 있다.

이런 구조를 다루려면 문제를 작은 버전으로 쪼개서 접근하는 기술이 필요하다 → 다음 주제: **Recursion**.
