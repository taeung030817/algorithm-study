# 8. Graph Algorithms (그래프 알고리즘)

## 개념

그래프는 점(node)과 연결(edge)로 이루어진 구조다.

- **Node**: 도시, 사용자, 웹페이지, 작업(task) 등을 표현할 수 있다.
- **Edge**: 도로, 친구 관계(friendship), 링크, 의존성(dependency) 등을 표현할 수 있다.

이름이나 도시 같은 세부 사항을 걷어내고 나면, 서로 완전히 다른 시스템도 "노드 + 간선"이라는 동일한 기본 구조를 공유한다.

## 알고리즘을 고르기 전에 확인할 것

1. 간선이 단방향인가, 양방향인가?
2. 간선에 비용(거리, cost)이 있는가?
3. 순환(cycle) 구조가 존재하는가?
4. 우리가 필요한 게 "가장 저렴한 것"인가, "경로 자체"인가?

## 인접 리스트 (Adjacency List)

그래프를 표현하는 대표적인 방법이다. 각 노드가 자신과 연결된 노드들의 목록을 갖는다.

**예시**: 삼각형 모양으로 연결된 `a - b - c - a`

```
a: [b, c]
b: [a, c]
c: [a, b]
```

## BFS (Breadth-First Search)

시작 노드에서 물결이 퍼져나가듯 한 번에 한 층씩 탐색한다.

- 먼저 거리 1(한 간선)로 도달 가능한 모든 노드를 방문
- 그다음 거리 2(두 간선)로 도달 가능한 모든 노드를 방문
- 이런 식으로 계층별로 확장

**필요한 두 가지 도구**
- **Queue**: 가까운 노드부터 어떤 순서로 처리할지 관리
- **Visited set**: 이미 방문한 노드를 기록해서 중복 작업과 순환에 갇히는 것을 방지

**왜 최단 경로에 좋을까**: BFS는 거리 기준으로 탐색하기 때문에, 어떤 노드를 처음 발견했을 때 그 경로가 항상 가장 적은 수의 간선을 사용한 경로다. 그래서 **가중치 없는 그래프**에서 최단 경로를 찾는 데 이상적이다.

## DFS (Depth-First Search)

BFS와 완전히 다르게 동작한다. 가능한 경로를 끝까지 쭉 따라가다가, 더 갈 곳이 없으면 마지막 분기점으로 되돌아가서 다른 경로를 시도한다.

스택을 직접 사용하거나, 재귀(함수 호출 스택을 그대로 활용)로 구현한다.

DFS가 유용한 경우: 도달 가능성 확인, 연결된 그룹(connected component) 찾기, 순환(cycle) 감지 등.

## 시간복잡도

인접 리스트를 사용하는 경우, BFS와 DFS 모두 각 노드와 각 간선을 한 번씩만 순회하므로 시간복잡도는 **O(V + E)** (V: 노드 수, E: 간선 수)다.

## 간선에 비용이 있다면: Dijkstra

간선마다 비용(가중치)이 있을 때는, 간선 수가 가장 적은 경로가 항상 가장 저렴한 경로는 아니다.

Dijkstra 알고리즘은 지금까지 알려진 비용이 가장 저렴한 노드를 반복적으로 선택하고, 그 노드를 거쳐서 이웃 노드까지 가는 경로가 기존에 알던 것보다 더 저렴한지 확인한다 (모든 노드와 무조건 연결해보는 게 아니다). 이 업데이트 과정을 **relaxation(완화)**이라고 부른다.

- Dijkstra는 **비용이 음수가 아닐 때** 최단 경로를 보장한다.
- 음수 비용이 있는 그래프에서는 **Bellman-Ford** 같은 알고리즘이 필요하다.

## 목적지가 있을 때 더 똑똑하게: A*

A*는 Dijkstra에 "지침(heuristic)"을 하나 추가한 것이다. 지금까지 이동한 실제 거리와, 목적지까지 남은 거리의 추정치를 결합해서 다음 노드를 선택한다.

이 추정치가 실제 거리를 과장하지만 않는다면(admissible heuristic), A*는 여전히 최적의 경로를 보장하면서도 목적지 방향으로 더 효율적으로 나아간다.

## 특정 경로가 아니라 "전체를 잇는" 문제라면

때로는 특정 두 지점 사이의 경로가 필요한 게 아니라, 모든 대상을 가장 싸게 연결하는 방법이 필요할 때도 있다. 이런 문제를 **최소 신장 트리(MST, Minimum Spanning Tree)** 문제라고 한다.

### Prim's Algorithm
하나의 노드에서 시작해서, 매번 "지금 연결된 네트워크에서 갈 수 있는 가장 저렴하고 안전한 연결"을 하나씩 추가하며 네트워크를 넓혀간다.

### Kruskal's Algorithm
전체 간선 중 가장 싼 것부터 순서대로 고려한다. 다만 그 간선을 추가했을 때 순환(cycle)이 생긴다면 건너뛴다. (싼 선부터 하나씩 골라 반복)

두 알고리즘 모두 **두 지점 사이의 최단 경로가 아니라, 전체 네트워크를 가장 저렴하게 연결하는 방법**을 만든다는 공통점이 있다.
