# 7. Dynamic Programming (동적 프로그래밍)

## 해싱에서 이어지는 아이디어

Hashing은 정보를 빠르게 "기억"하는 방법을 제공했다. Dynamic Programming은 이 기억하는 방식을 문제 풀이 전략으로 확장한 것이다. 작은 문제에 대한 답을 저장해두기 때문에, 같은 답을 두 번 계산할 필요가 없다.

## 피보나치 예시: 왜 naive 재귀는 느릴까

피보나치 수는 바로 앞 두 수의 합이다. 재귀로 풀면 자연스럽다.

`fib(5)`를 구하려면 `fib(4)`와 `fib(3)`이 필요하고, `fib(4)`는 다시 `fib(3)`을 요구한다. 즉 같은 질문이 반복해서 등장한다. 매번 답을 "까먹고" 처음부터 다시 계산하는 셈이다.

입력이 커질수록 이 반복 작업량은 기하급수적으로 늘어난다 (O(2ⁿ)).

## Top-down: Memoization

"같은 질문이 다시 나올 가능성이 있다면, 답을 저장해두자"는 게 핵심 아이디어다.

재귀 구조는 거의 그대로 두고, 캐시(cache)를 하나 추가해서 모든 입력에 대한 결과를 기억한다.

- 어떤 번호에 대한 첫 번째 요청은 정상적으로 계산한다.
- 그 이후 같은 번호에 대한 요청은 저장된 답을 즉시 반환한다.

이 방식을 **memoization**이라고 하며, 재귀를 유지한 채 최종 값에서 아래로(top-down) 내려가며 계산하기 때문에 이렇게 부른다.

```
fib(5)
├── fib(4)
│   ├── fib(3)
│   │   ├── fib(2) → 계산 후 저장
│   │   └── fib(1) → 1
│   └── fib(2) → 저장된 값 재사용
└── fib(3) → 저장된 값 재사용
```

각 값을 딱 한 번씩만 계산하기 때문에, 시간복잡도가 지수함수(O(2ⁿ))에서 **O(n)**으로 줄어든다.

## Bottom-up: Tabulation

재귀 호출이 반드시 필요한 건 아니다. 이미 알고 있는 값(`fib(0)=0`, `fib(1)=1`)부터 시작해서 n까지 순서대로 차근차근 올라갈 수도 있다. 이 방식을 **tabulation**(표로 정리하기)이라고 한다.

피보나치는 바로 앞 두 개의 답에만 의존하기 때문에, 테이블 전체를 유지할 필요 없이 변수 두 개면 충분하다.

```python
a, b = 0, 1
for _ in range(n):
    a, b = b, a + b
```

이 방식의 이점: 계산 순서를 직접 통제할 수 있고, 일정한(고정된) 추가 메모리만 사용하며, 재귀 호출 스택이 필요 없다.

## Memoization vs Tabulation

- **Memoization**: 최종 값에서 아래로 내려가면서, 실제로 필요한 단계만 계산한다 (top-down).
- **Tabulation**: 작은 값부터 시작해서 의도한 순서대로 값을 차곡차곡 쌓아 올린다 (bottom-up).

## Dynamic Programming 문제임을 알아보는 두 가지 단서

1. 동일한 작은 문제가 반복적으로 나타난다
2. 큰 문제의 답이 작은 문제들의 답을 조합해서 만들어질 수 있다

## 진짜 어려운 부분: 테이블을 채우는 게 아니라 "상태"를 정의하는 것

### 예시: 최대 부분 배열 (Maximum Subarray)

배열에서 연속된 구간을 골라, 그 구간의 합이 최대가 되는 값을 찾는 문제다.

현재 위치에서 이전 구간을 이어가는 게 유리한지, 아니면 여기서 새로 시작하는 게 유리한지를 매 단계 판단한다. 이 아이디어를 상수 추가 메모리만으로 배열을 한 번만 스캔해서 푸는 방식이 **카데인 알고리즘(Kadane's Algorithm)**이다.

```python
current = max(nums[i], current + nums[i])   # 이어갈지, 새로 시작할지
best = max(best, current)                    # 지금까지의 최댓값 갱신
```

- `current`: 현재 위치에서 끝나는 부분 배열의 최댓값
- `best`: 지금까지 나온 모든 부분 배열 중 최댓값

**예시**: `[-2, 1, -3, 4, -1, 2, 1, -5, 4]`

```
i=0 (-2): current=-2, best=-2
i=1 (1):  current=max(1, -2+1)=1,   best=1
i=2 (-3): current=max(-3, 1-3)=-2,  best=1
i=3 (4):  current=max(4, -2+4)=4,   best=4
i=4 (-1): current=max(-1, 4-1)=3,   best=4
i=5 (2):  current=max(2, 3+2)=5,    best=5
i=6 (1):  current=max(1, 5+1)=6,    best=6
i=7 (-5): current=max(-5, 6-5)=1,   best=6
i=8 (4):  current=max(4, 1+4)=5,    best=6
결과: 6   (구간 [4, -1, 2, 1])
```

이 값을 저장하는 데 필요한 건 변수 몇 개뿐이라 **상수 메모리 O(1)**로 충분하다. 입력 크기가 커져도 변수 개수는 그대로다.

## 핵심

Dynamic Programming은 공식을 암기하는 게 아니다. 반복되는 하위 작업을 알아차리고, 올바른 "상태"를 정의하고, 그 상태의 답을 보존하는 것이다.

각 상태를 하나의 점(node)으로 표현하고 상태들 간의 의존 관계를 그림으로 그려보면, 마치 하나의 네트워크처럼 보인다.
